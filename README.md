# QAI — воркшоп для тестировщиков

На воркшопе вы попробуете работать с агентом, который помогает расследовать ошибки: проверите его ответ, измените инструкцию, подключите источник данных и допишете небольшой инструмент для поиска логов.

Занятие длится 2,5 часа: час знакомства и запуска подготовленного окружения, 30 минут перерыв и час практики.

## С чего начать

1. **До занятия:** откройте [подготовку ноутбука](docs/participant-prework-draft.md). Выберите одну программу — Codex, Claude Code, Cursor или Python.
2. **На занятии:** откройте [стартовую страницу](docs/workshop-kit.md). Там ссылки на четыре задания.
3. **После занятия:** посмотрите, [как повторить подход в своём проекте](docs/monday-replay-guide.md).

Если ищете конкретную настройку или объяснение, используйте [указатель документации](docs/README.md).

## Что понадобится

Подготовленный Python, Docker и выбранная программа с доступом к модели. Для редактора используйте его авторизацию; отдельный API-ключ для учебного MCP не нужен. Стандартный Python-запуск требует настроенного API-провайдера. Облачной модели нужен интернет.

Для установки без скачиваний нужен полный комплект ведущего: исходники, образы, Python-пакеты и инструменты. Одного клонирования этого репозитория недостаточно.

Проверен запуск на macOS Apple Silicon / Python 3.12.6 / уже установленном Docker 4.42.1. Установка приложенного Docker 4.91.0/VMM на чистом Mac и работа на Windows/Linux/Intel не подтверждены тем же прогоном. Для своей системы откройте [инструкцию Mac](docs/new-macbook-offline.md) или [Windows x64 / WSL2](docs/setup-windows.md) и заранее проверьте подготовку с ведущим.

## Как устроена практика

Сначала работаем с готовыми файлами. В третьем задании читаем данные отдельного учебного Kubernetes. В четвёртом снова используем файлы — другой случай с неправильной суммой заказа. Учебные неисправности не исправляем: задача — получить данные и проверить объяснение.

Агент сам выбирает, какие сведения запросить дальше. Код ограничивает доступные действия и проверяет отчёт. Даже успешную автоматическую проверку нужно дополнить чтением источников. Устройство системы подробно описано в [разборе оркестратора](docs/model-orchestrator.md).

Решения, подсказки, презентации и готовые ответы хранятся у ведущего отдельно. Свою работу сохраняйте в `workshop/.local/`. Секреты и kubeconfig не добавляйте в Git.

## Проверить подготовленное окружение

Из корня проекта, на macOS/Linux:

```bash
workshop/.venv/bin/python workshop/offline/check.py
```

Эта команда проверяет локальные файлы и зависимости без модели и живого кластера. Полная подготовка включает также шаги из инструкции вашей ОС.

## Дополнительно: запуск Python-агента

Только если вы выбрали Python, настроили API модели и уже подготовили стенд:

```bash
workshop/.venv/bin/python workshop/e2e.py --read-only BUG-1024
```

Это настоящее расследование, а не проверка установки. Фиксированный порядок ролей можно выбрать через `--mode workflow`. Для четвёртого задания используйте команды его карточки: там есть отдельный вариант Python с Codex по подписке.

## Где что лежит

- `workshop/exercises/` — задания.
- `workshop/prompts/` — инструкции ролей.
- `workshop/skills/` — инструменты агента.
- `fixtures/` — учебные данные.
- `docs/` — подготовка и справочные материалы.
- `tests/` — проверки кода.
- `microservices-demo/` и `workshop/services/order-worker/` — код исследуемых сервисов.

Общие правила находятся в `AGENTS.md`. Файлы для редакторов создаёт `workshop/render.py` из общих исходников.

## Дополнительно: проверки кода

```bash
workshop/.venv/bin/python -m unittest discover -s tests/workshop -v
python3 workshop/render.py --check
```

Это проверки механизмов, без закрытых решений и ключей оценки ведущего. В задании 4 проверяйте свою функцию командой `check` из карточки. Пока в функции TODO, её FAIL ожидаем.
