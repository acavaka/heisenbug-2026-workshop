# Подготовка к QAI-воркшопу

Формат: 60 минут вводной и запуска подготовленного окружения, 30 минут перерыв,
60 минут практики. Подготовьте ноутбук за 5–7 дней: устанавливать Docker и редактор,
загружать образы и зависимости в практический час не будем.

## Комплект и проверенный маршрут

Версия комплекта указана в корневом `README.md` USB-набора и в `MANIFEST.json`
внутри распакованного проекта. Ведущий выдаёт USB-каталог `qai-usb` или его полную копию. В нём:

- `qai-participant.zip` — исходники, четыре задания и проверки контракта;
- `python-wheels/` — 39 локальных wheels для выбранной платформы / Python 3.12;
- `tools/` — Kind, kubectl и k8sgpt;
- `images/workshop-images.tar.gz` — 23 локальных образа;
- `installers/` — установщики выбранной платформы (Mac: Docker/Python; Windows: Docker/WSL/Ubuntu с Python);
- `USB-MANIFEST.json` и `USB-SHA256SUMS.txt` — состав и контрольные суммы.

Открывайте в редакторе только распакованный `qai-participant`. Подсказки, готовые решения,
ключи eval и материалы ведущего в комплект участника не входят. Они хранятся у ведущего
отдельно и не должны находиться в рабочем каталоге, доступном вашему агенту.
Один ZIP не содержит wheels, бинарники и образы: для подготовки без скачиваний нужен весь USB-каталог.
Ссылка на получение копии сообщается ведущим вместе с этой инструкцией; публичный URL
этим документом не устанавливается. После получения сверяйте состав и хеши из самого комплекта.

**Проверено:** macOS Apple Silicon, Python 3.12.6, установленный Docker Desktop 4.42.1
и запуск нового отдельного Kind из USB. Набор включает Kind 0.27.0, kubectl 1.31.1,
k8sgpt 0.4.40, node `kindest/node:v1.32.2`. Используйте эти версии из комплекта.

**Граница проверки:** установщики Docker 4.91.0 Apple Silicon и Python 3.12.6 universal2
включены, но установка на совершенно чистом Mac и Docker VMM не проверены.
Stock Boutique использует amd64-образы, остальные образы включают arm64;
на Apple Silicon нужна проверка эмуляции из инструкции ниже. Это не универсальный пакет для всех CPU.
Для Windows 11 x64 подготовлен отдельный комплект WSL2: [маршрут и границы проверки](setup-windows.md).
Установка на настоящем Windows ещё требует предварительной проверки; Linux и macOS Intel отдельно не сертифицированы.
Заранее согласуйте с ведущим подготовку своей машины. Replay помогает продолжить разбор, но не засчитывает живое подключение k8sgpt.

## Что подготовить

Понадобятся ноутбук, зарядка, работающий Docker Engine, Python и привычная программа:
Codex, Claude Code, Cursor или Python-харнесс. Все редакторы устанавливать не нужно.
Клиент модели не входит в USB: установите и авторизуйте его заранее.
Подписка редактора не требует OpenAI API-ключа. Стандартный Python-харнесс использует
API-провайдера; endpoint, модель и ключ подготовьте отдельно, не публикуйте их.
В файловом задании BUG-LAB-01 Python также поддерживает транспорт Codex по подписке;
это отдельный маршрут карточки, не замена API для всех Python-команд.

Локальные зависимости и стенд устанавливаются с USB без скачиваний. Облачной модели
всё равно нужен интернет и доступ к аккаунту. Корпоративные ограничения Docker,
виртуализации и доступа к модели выясните до мероприятия.

Ориентир комфортной машины: 16 GB RAM и 25–30 GB свободного места; для Docker около
4 CPU и 8 GB RAM. Это рекомендация, не измеренный минимум. При 8 GB RAM или отсутствии
прав установки заранее договоритесь о работе в паре. Go, Java, .NET, Helm, Skaffold,
локальные Postgres и Temporal CLI обязательным упражнениям не нужны.

## Установить и запустить с USB

Для Mac: [MacBook с USB](new-macbook-offline.md). Для Windows используйте [отдельный маршрут WSL2](setup-windows.md): команды ниже относятся к Mac.
Если Docker и Python уже установлены, начните с проверки версий и PATH в шаге 3;
сначала прочитайте границы проверки и состав комплекта. Команды ниже — ориентир;
определение `QAI_USB`, `QAI_PROJECT`, PATH, распаковка и загрузка образов описаны там полностью.
Не смешивайте разные выпуски, рабочие каталоги или старые tar-файлы.

1. Проверьте USB-SHA256SUMS.txt, версии инструментов и работающий `docker info`.
2. Распакуйте участника в новый каталог; установите wheels локальным installer.
3. Загрузите образы через docker load; выполните отдельную проверку amd64-эмуляции
   и preflight_images.py по USB-инструкции. Не используйте docker pull/build.
4. Для нового стенда используйте только строгий launcher:

```bash
cd "$QAI_PROJECT"
workshop/.venv/bin/python workshop/offline/launch.py --usb "$QAI_USB" --allow-amd64-emulation
export KUBECONFIG="$QAI_PROJECT/workshop/.local/kind.kubeconfig"
workshop/.venv/bin/python workshop/offline/verify_stand.py --context kind-qai-boutique --kubeconfig "$KUBECONFIG" --timeout 0
```

Флаг эмуляции допустим после отдельной проверки из шага 5 USB-инструкции.
Launcher откажется менять существующий кластер или перезаписывать kubeconfig.
Если стенд уже подготовлен, не создавайте его повторно: проверьте готовность с его kubeconfig.
Прямой `up-offline.sh` не является маршрутом участника: его сообщение Done не заменяет
проверку Ready всех 18 Deployment. ImagePullBackOff — ошибка подготовки, а не учебный баг.

5. Откройте HTTP-интерфейсы и выполните read-only check_http.py по шагу 6 USB-инструкции.
   Не используйте verify-stack.sh для read-only проверки: он создаёт учебные данные.
6. Вместе с ведущим подготовьте отдельный `qai-training` и личный read-only профиль
   по шагу 7. Не копируйте административный kubeconfig или чужие ключи.

Все дальнейшие команды выполняются из корня участника с `workshop/.venv`.
Локальный installer использует --no-index и --require-hashes, не перезаписывает venv
и не имеет fallback на скачивание. Подробности: [offline](../workshop/offline/README.md).

## Подготовить модель и MCP

- Проверьте ответ модели в выбранной программе до занятия; ключи и личные настройки не отправляйте ведущему.
- Для редакторного задания 4 заранее подключите [application MCP](application-mcp.md):
  `--mode replay --case complete`. Проверьте список инструментов
  и пустое расследование через qai_begin/qai_catalog. BUG-LAB-01 заранее не расследуйте.
- Бинарник k8sgpt и Python/MCP-зависимости должны быть готовы заранее.
  Само подключение [k8sgpt через MCP](k8sgpt-mcp.md) выполняем в задании 3.
  Application и infrastructure используют разные серверы и каталоги; ID не смешиваем.
- Для API-маршрута создайте собственный workshop/.env из .env.example.
  Для editor replay API-ключ и адреса стенда application MCP не нужны; сервер .env автоматически не читает.

## Проверка готовности до встречи

Можно ответить «готов», если:

- проект и карточки открываются, выбранная модель отвечает;
- локальная Python-проверка проходит, образы и сервисы подготовлены;
- HTTP-интерфейсы доступны, учебный неисправный Pod в qai-training ожидаем;
- есть собственный read-only профиль; application MCP обнаруживается, k8sgpt-бинарник доступен;
- вы знаете, где сохранять свои результаты: workshop/.local/.

Заготовка correlate ещё не реализована: FAIL её проверки до задания 4 ожидаем.
Не исправляйте Boutique, order-worker, учебную неисправность и валидатор.
Если подготовка не проходит, заранее сообщите ведущему ОС/CPU, шаг, команду и ошибку,
без .env, токенов и kubeconfig. Согласуйте помощь или пару до начала практического часа.
