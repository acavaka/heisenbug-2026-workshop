# Новый инструмент QAI

Инструмент — исполняемая функция и schema. Его можно вызывать явно через CLI или предоставить модели. Роль/Agent Skill описывает, как выбирать и применять инструменты; эти понятия не взаимозаменяемы.

1. Скопируйте `workshop/skills/_template.py`, переименуйте функцию, schema и impl.
2. Реализуйте `_fetch_rows`: запрос только на чтение, реальный timeout, ограничение числа строк на стороне клиента API. Не добавляйте URL/credentials в ответ или сообщение об ошибке.
3. Укажите в description источник, условия применения, формат аргументов и границы вывода. Schema и функция должны одинаково ограничивать параметры: schema сама по себе не валидирует Python-вызов.
4. Зарегистрируйте функцию/schema в `skills/__init__.py`; выдайте инструмент нужной роли в `prompts/`; выполните `python workshop/render.py` и `--check`.
5. Проверьте CLI и agent loop на синтетических данных: успех, пустой ответ, ошибка источника, невалидный параметр, превышение лимита и длинный JSON.

## Результат

Шаблон возвращает `ToolResult` с JSON и `is_error`. Python и CLI учитывают is_error, даже если в тексте нет префикса ERROR. Ошибка незаполненной заготовки — `not_implemented`, а не фиктивный успех.

- `status=ok`: данные получены; это не подтверждение причины.
- `status=empty`: успешная пустая выборка; отсутствие события за её границами не доказано.
- `status=error`: источник/аргументы/реализация не позволяют получить данные.
- `truncated`: лишние строки не вошли в результат.
- `complete=false`: шаблон не доказывает полноту истории.
- `source`: логическое имя источника, без секретов.

Шаблон запрашивает limit+1 строку, чтобы определить обрезание, и возвращает максимум limit. Ограничение строк не ограничивает размер одной строки: для источников с крупными записями нужен отдельный структурированный интерфейс пагинации/фрагментов. Никогда не используйте `json_text[:N]`.

Runtime сохраняет полный исходный ответ в observation. В модельном контексте JSON-объекты/массивы сохраняются целиком; большой обычный текст сокращается с явной отметкой. Это не бесконечный бюджет контекста: источник должен давать осмысленные ограниченные выборки. Хранилище исходных данных и способ их выдачи модели — разные обязанности.

При реализации проверьте обязательные аргументы, отказ внешнего источника и формат результата. Сам шаблон не зарегистрирован и не делает сетевых запросов до реализации адаптера. Валидатор доказательств не изменён.

## Exit code полного e2e

`python workshop/e2e.py --read-only <BUG-ID>`:

- 0 — все обработанные вердикты приняты контрактом, включая корректное воздержание low;
- 1 — отклонённый контракт либо техническая ошибка/отсутствующая настройка;
- 2 — пустой вызов без BUG-ID.

В batch отклонённый вердикт сохраняется, остальные группы обрабатываются, итоговый код — 1. Принятый low не означает найденную причину. Exit 0 не заменяет behavioral eval или ручную оценку семантики. Ошибка выполнения с исключением завершает процесс ненулевым кодом; возобновление batch после произвольного исключения пока не реализовано.
