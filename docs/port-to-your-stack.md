# Перенос QAI на свой проект

Начните с [файлового replay](monday-replay-guide.md), затем подключите один разрешённый
источник и один класс задач. Срок зависит от API, доступа и формата наблюдений;
двух замен функций недостаточно, чтобы считать расследование проверенным.

| Источник воркшопа | Пример замены | Что проверить |
|---|---|---|
| tracker.py и context_fixtures.py | Корпоративный трекер и база знаний | Read-only доступ, ID задачи, происхождение требований |
| cluster_logs.py | Централизованные логи | Точные request/trace ID, окно, пагинация, отличие ошибки от пустой выборки |
| tempo.py | Другая система трассировки | Сохранение JSON, отсутствующие spans и временные границы |
| temporal_inspect.py | Workflow вашего сервиса, TEMPORAL_HOST и TEMPORAL_NAMESPACE | Read-only поиск, describe и страницы истории точного workflow_id + run_id; см. [Temporal](temporal-tools.md) |
| code.py | Разрешённый checkout исходников | Корни чтения, версия кода, точные file:line |
| MCP k8sgpt | Диагностика инфраструктуры | Namespace, read-only RBAC, разрешённые операции и наблюдения |

Пример подключения нового инструмента — [tool-authoring](tool-authoring.md), реализация
заготовки — workshop/skills/_template.py. Укажите схему, реализуйте адаптер, зарегистрируйте
его и выдайте нужной роли, затем выполните python workshop/render.py.
Для нового типа источника также проверьте регистрацию в MCP и каталоге доказательств:
описание скилла само по себе не создаёт проверенное наблюдение.

Ошибки возвращайте по контракту ToolResult, сохраняя статус и метаданные; не превращайте
таймаут в «ничего не найдено». Ограничивайте запрос и количество результатов структурно,
показывайте пагинацию и truncation; не обрезайте сериализованный JSON по символам.
Новый source должен проходить прежние требования происхождения и роли доказательства.

Произвольный postgres_query в строгом read-only профиле отключён: legacy-подключение
использует административную роль. Для БД нужна отдельная роль чтения и ограниченный
инструмент запросов, а не только новая строка подключения. Секреты и пользовательские
данные не включайте в учебные фикстуры, отчёты и репозиторий.

1. Сформулируйте вопрос, наблюдаемый симптом и критерии достаточного evidence.
2. Подготовьте контролируемые случаи: известная причина, недостаточные данные, ложный след,
   недоступный источник. Сохраните ожидаемое поведение и отрицательные критерии.
3. Проверьте адаптеры локально, затем расследование и [eval](agent-eval.md).
4. Сохраните вердикт как артефакт для ручной проверки; запись в трекер требует отдельного решения.
5. Добавляйте новые источники и CI после проверки конкретного сценария. Примеры CI/deploy
   в проекте — отправная точка, а не готовый production quality gate.

В Python итог принимает runtime; в редакторах — фактический qai_validate правильного MCP.
Read-only отключает запись runbook. Вне него допустимый application high может записывать
подтверждённый паттерн; это внешняя память, а не обучение весов модели.
