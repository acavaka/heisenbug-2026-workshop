# Зачем Python-харнесс на воркшопе

Python-харнесс показывает прозрачный пример цикла модель → инструмент → наблюдение →
ответ → проверка. Не превращать обязательную практику в разработку полноценной платформы.
Участники выбирают привычный клиент; инструменты, учебные данные и требования к доказательствам общие.

Наши прогоны не являются сравнением качества платформ: Python использовал gpt-4o-mini/gpt-4.1,
Codex — свою модель и контекст. Для причинного сравнения нужны одинаковые модель, бюджет,
источники, задача и несколько повторов. Пока мы сравнили конкретные конфигурации.

## Три подхода

- Готовый агент: начать с инструментов, скиллов и правил проекта. Hermes имеет систему skills,
  совместимую с Agent Skills: [официальная документация](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills).
  Короткое файловое демо ведущего показывает переносимость правил; оно не проверяет live Kubernetes.
- Фреймворк: LangChain даёт абстракции моделей, инструментов и агентного цикла;
  LangGraph — управление состоянием, сохранение исполнения и участие человека.
  [Границы компонентов](https://docs.langchain.com/oss/python/langgraph/overview).
- Небольшой собственный цикл: полезен для обучения и простого контролируемого сценария;
  поддержка состояния, интерфейсов и эксплуатационной надёжности становится нашей работой.

Выбор runtime не отменяет предметную проверку: какой запрос расследован, чем подтверждён
вывод, какие данные недоступны. Это инженерный вывод, а не результат сравнительного бенчмарка.
Миграцию на фреймворк не добавляем в 60 минут практики.

## Что проверять независимо от платформы

Пользовательский результат — проверенное расследование. Eval помогает заметить, когда замена
модели или промпта возвращает известную ошибку. Для учебной задачи достаточно конечной рубрики;
для рабочих багов нужны разнообразные случаи и ручная оценка причинности. Валидный JSON
и наблюдаемые цитаты сами по себе не гарантируют правильность диагноза.
