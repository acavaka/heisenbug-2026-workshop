# 1. Проверить расследование — 8 минут (0–8)

**Результат:** два проверенных факта, один необоснованный вывод и следующий запрос данных.
Работаем с сохранённым синтетическим расследованием; запуск модели и доступ к Kubernetes не нужны.
Можно попросить агента помочь, но каждую выбранную цитату проверьте сами.
Это аудит результата, а не новый запуск оркестратора. Порядок ролей по этому файлу не восстанавливаем: в текущем агенте роли и досбор выбирает модель. Принятый JSON тоже может содержать неверную интерпретацию — поэтому нужна ваша проверка.

## Что открыть

Из корня репозитория откройте в своём редакторе:

- [BUG-INFRA-01](../../../fixtures/tracker/BUG-INFRA-01.md) — исходное обращение;
- [сохранённый ответ агента](../../../fixtures/behavioral/infra-startup/known-bad-healthy.json).

Ответ намеренно содержит ошибку. Источники для проверки находятся в его `tool_observations`:
`tool`, `args`, `status`, `result`. Поля `claim`, `reasons` и `root_cause` — утверждения агента,
а не независимые доказательства. Не открывайте ответ ведущего до самостоятельной попытки.

## По минутам

| Минуты задания | Что сделать |
|---|---|
| 0–2 | Прочитать репорт и `root_cause`. Сформулировать, что именно утверждает агент. |
| 2–5 | Сопоставить утверждение с исходными ответами инструментов. Проверить объект и границы наблюдения. |
| 5–7 | Записать результат по шаблону ниже. Назвать конкретный следующий запрос и зачем он нужен. |
| 7–8 | Объяснить соседу, что доказано, а что осталось неизвестным. |

Сохраните заметку в `workshop/.local/exercise-01.md` (создайте каталог, если его нет):

```text
Программа участника (Python-маршрут / Codex / Cursor / Claude Code, не имя компьютера):
Источник данных: сохранённый synthetic replay, не live
[ФАКТ] ...; tool + args + дословный фрагмент result:
[ФАКТ] ...; tool + args + дословный фрагмент result:
Необоснованный вывод агента:
Почему приведённые данные его не доказывают:
Чего ещё нельзя заключить по этим данным:
Следующий запрос: источник + фильтр/недостающий ID + проверяемый вопрос:
```

## Приёмка

- Оба факта сверены с `tool_observations`, а не только с текстом вердикта.
- Найден конкретный скачок от наблюдения к диагнозу; пояснено противоречие.
- Не придумана новая причина вместо отвергнутой и не объявлено приложение исправным.
- Следующий запрос сужает расследование: указаны нужные данные и способ связать их с инцидентом.
- Текущее состояние не выдано за историю работы сервиса; replay не назван live.

Если к минуте 4 не нашли противоречие, попросите первую подсказку у ведущего.
**Для быстрых:** проверьте отдельно claim про конфигурацию и вывод из пустого списка событий.
