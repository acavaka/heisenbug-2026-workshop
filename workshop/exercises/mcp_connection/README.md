# 3. Подключить k8sgpt через MCP — 15 минут (20–35)

**Результат:** агент сам вызывает настоящий k8sgpt через MCP, получает инфраструктурные
наблюдения и выдаёт проверенный вердикт. Установка пакетов и подготовка Kubernetes завершены
в prework/первой части. Здесь вы самостоятельно подключаете интеграцию к своему хосту.

Работаем только на чтение в `qai-training`. Не исправляем найденную неисправность.
Boutique, order-worker, другие namespaces и Secrets не читаем и не меняем в этом упражнении.

## До начала таймера

Ведущий подтвердил готовность вашего локального учебного namespace, k8sgpt и отдельного
read-only доступа. У вас есть `workshop/.local/mcp-live.json` с абсолютными локальными путями
и `exclusive: true`. Файл создан для этого ноутбука, его нельзя копировать с чужой машины.
Не открывайте и не отправляйте агенту содержимое kubeconfig или токены.
Если подготовка не завершена — сразу к ведущему; установка кластера не входит в эти 15 минут.

Все команды ниже — из корня репозитория, в готовом `workshop/.venv`.

| Минуты задания | Действие |
|---|---|
| 0–4 | Добавить подключение для своего хоста и проверить доступность инструментов. |
| 4–10 | Запустить расследование; найти Pod, получить spec/status и его события. |
| 10–13 | Проверить вердикт, ссылки на улики и идентичность ресурса. |
| 13–15 | Сохранить результат и объяснить границы диагноза. |

## Python-харнесс

В терминале macOS/Linux:

```bash
export QAI_MCP_CONFIG="$PWD/workshop/.local/mcp-live.json"
export REPORTS_DIR="$PWD/workshop/.local/exercise-03-live"
export AGENT_TRACES=0
python workshop/mcp_check.py --config "$QAI_MCP_CONFIG"
python workshop/e2e.py --read-only BUG-INFRA-LIVE-01
```

В PowerShell:

```powershell
$env:QAI_MCP_CONFIG = (Resolve-Path workshop/.local/mcp-live.json).Path
$env:REPORTS_DIR = Join-Path (Get-Location).Path 'workshop/.local/exercise-03-live'
$env:AGENT_TRACES = '0'
python workshop/mcp_check.py --config $env:QAI_MCP_CONFIG
python workshop/e2e.py --read-only BUG-INFRA-LIVE-01
```

Это режим `agent` по умолчанию: модель выбирает роли, классификацию и досбор; Python
исполняет разрешённые вызовы и валидирует результат. Фиксированный `--mode workflow`
для этого задания не выбираем. Доступ к модели уже настроен до таймера.

Если каталог отчётов уже использовали, задайте новое имя до запуска. `mcp_check` проверяет
handshake и список инструментов, но не успешность чтения Pod. Нужен следующий за ним e2e.
В итоговом `BUG-INFRA-LIVE-01.json` проверьте реальные `tool_observations`, `mode: live`,
аргументы namespace и отсутствие `validation_errors`. Сохранённый low с ошибками валидации
не является принятым диагнозом. После упражнения закройте этот терминал, чтобы переменные
live-профиля не переносились в последующие файловые упражнения.

## Claude Code / Codex / Cursor

Выберите одну команду для своего хоста:

```bash
python workshop/mcp_config.py --host claude --profile live
python workshop/mcp_config.py --host codex --profile live
python workshop/mcp_config.py --host cursor --profile live
```

Генератор только печатает фрагмент. В его `args` **замените путь к `live.example.json` на
абсолютный путь к вашему `workshop/.local/mcp-live.json`**. Оставьте путь к gateway и Python
из активного venv. Для этого подготовленного профиля `QAI_KUBECONFIG` не нужен:
бинарник и read-only kubeconfig уже указаны внутри локального JSON; в Codex удалите
напечатанную строку `env_vars = ["QAI_KUBECONFIG"]` из добавляемого фрагмента.

| Хост | Куда добавить фрагмент |
|---|---|
| Claude Code | `.mcp.json`, секция `mcpServers.k8sgpt` |
| Codex | доверенная проектная `.codex/config.toml`, секция `[mcp_servers.k8sgpt]`; либо пользовательская конфигурация |
| Cursor | `.cursor/mcp.json`, секция `mcpServers.k8sgpt` |

Добавляйте секцию, сохраняя существующие серверы. Если `k8sgpt` уже настроен на replay,
сохраните прежние настройки и обновите эту секцию: не создавайте второй одноимённый сервер.
Переподключите MCP/перезапустите сессию. Найдите `qai_begin`, `qai_observe`, `qai_catalog`,
`qai_evidence_get`, `qai_validate` и инструменты k8sgpt. Префиксы имён зависят от хоста.
В этом задании выбирайте **сервер k8sgpt**, а не qai_application из файлового задания 4.
У них похожие имена операций, но разные источники, каталоги и контракты доказательств.
Если доступны только пять upstream-инструментов, проверьте, что подключён `mcp_gateway.py`.

В интерактивном Codex подтвердите запрошенные вызовы учебного MCP после проверки сервера
и аргументов. Разрешение на чтение файлов не означает разрешение на вызовы MCP.
Ошибка `MCP tool call requires approval, but approval policy is never` означает блокировку
на уровне хоста: данные ещё не прочитаны. Не отключайте sandbox и не выдавайте admin kubeconfig.
Обычному участнику нужен интерактивный режим с подтверждениями; для CLI-репетиции ведущего
обратитесь к ведущему за инструкцией для вашей версии клиента.

Затем передайте агенту:

```text
Расследуй BUG-INFRA-LIVE-01 по AGENTS.md и общим инструкциям QAI в workshop/prompts.
Прочитай fixtures/tracker/BUG-INFRA-LIVE-01.md и docs/evidence-contract.md.
Работай только через подключённый MCP k8sgpt, только на чтение, namespace qai-training.
Начни qai_begin. Через qai_observe найди Pod по app=checkout-probe; получи его spec/status
и события по фактическому имени Pod. Сохраняй один investigation_id во всех вызовах.
Сверь UID и время. Проверь collection_gaps; не выдумывай недостающие данные.
Составь вердикт по общим правилам, вызови qai_validate и покажи возвращённый результат.
Не читай kubeconfig/секреты. Не меняй стенд и не выполняй рекомендованное исправление.
```

`qai_observe` вызывает настоящий k8sgpt и регистрирует ответы в каталоге доказательств.
Прямой raw-вызов `get-resource` полезен для диагностики подключения, но не заменяет этот путь
для проверенного вердикта. При `qai_validate.valid: false` прочитайте errors и исправьте
ссылки/вывод по фактическим уликам; не повышайте confidence ради приёмки.

## Приёмка

Сохраните `workshop/.local/exercise-03.md`: хост, режим, путь к отчёту/транскрипту,
имена вызванных инструментов, namespace/name/UID, две ссылки на доказательства и результат валидации.
Для редактора сохраните возвращённый `verdict` и `valid`, а не только свободный пересказ.
Завершение Codex CLI с кодом 0 может означать ответ «заблокировано»; это не приёмка задания.

- Есть успешные **вызовы агентом** чтения ресурса и его событий через MCP, а не только tools/list.
- Это live k8sgpt; источник и фактические аргументы видны в ответах/наблюдениях.
- Диагноз связывает конфигурацию, состояние контейнера и Warning одного объекта; UID сверены.
- Python: вердикт прошёл runtime-валидацию; редактор: `qai_validate` вернул `valid: true`.
  Дополнительно человек проверил причинную связь и время. Валидный JSON сам по себе недостаточен.
- При неполных данных агент указал ограничения. Не требуется любой ценой получить high.
  Для полного прохождения нужна подтверждённая причина; корректное воздержание отмечаем
  как безопасный, но незавершённый результат расследования.
- Участник объясняет, почему исправление инфраструктурного запуска ещё не проверяет бизнес-функции.

Если к минуте 4 инструменты не появились, попросите подсказку и помощь ведущего.
На минуте 10 без данных — работа в паре на готовом подключении. Не тратьте время на починку стенда.
Replay допустим как явно обозначенный резерв, но не считается проверкой настоящего k8sgpt.
