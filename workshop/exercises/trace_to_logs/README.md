# 4. Создать trace_to_logs — 20 минут (35–55)

**Результат:** ваша функция корреляции проходит проверки, агент действительно использует её,
а итоговый application-вердикт принят общим валидатором и проверен вами по источникам.
Сюжет BUG-LAB-01: ошибка суммы при здоровых подах. Данные — **synthetic file replay**;
Kubernetes, Tempo и API приложения в этом задании не вызываются.

Работайте в Python-харнессе, Codex, Claude Code или Cursor. Код можно писать с агентом.
Меняем только description и `correlate` в `workshop/skills/trace_logs.py`. Не меняем fixtures,
adapters, проверки, код учебного checkout, Boutique, order-worker и стенд.
Решение ведущего и готовые отчёты до самостоятельной попытки не открываем.

## До начала таймера

Откройте корень проекта и готовое `workshop/.venv`. Все команды ниже — из корня.
Для macOS/Linux: `source workshop/.venv/bin/activate`; Windows PowerShell:
`workshop/.venv/Scripts/Activate.ps1`. Без активации замените `python` полным путём
`workshop/.venv/bin/python` или `workshop/.venv/Scripts/python.exe`.

Завершите live-расследование задания 3. Для Python откройте новый терминал без его
`QAI_MCP_CONFIG` и `REPORTS_DIR`. Для редактора — новый диалог и **qai_application** в режиме
replay, подготовленный в первой части по [инструкции](../../../docs/application-mcp.md).
Сервер k8sgpt в этом задании не используем. Новый баг — новый investigation_id.
Модель и зависимости должны работать заранее; установка не входит в 20 минут.

## 0–3: контракт и описание

```bash
python workshop/exercises/trace_to_logs/run.py report
python workshop/exercises/trace_to_logs/run.py pods
```

Прочитайте report и снимок pods. Измените description: когда вызывать инструмент, какие
поля он возвращает, почему соседняя строка без ID — только контекст.
Новый исполняемый скилл состоит из описания, схемы и функции; регистрация уже подготовлена.
Replay-обёртка имеет своё фиксированное описание области доступа; вашу правку description
проверяем отдельно, не приписываем ей эффект, если конкретный маршрут её не передавал модели.

## 3–11: реализация

Допишите `correlate` в `workshop/skills/trace_logs.py`. Адаптеры дают разобранные даты,
ID и исходные строки. Реализуйте окно времени, точные ID, matches/context, лимит и truncated.
Алгоритм должен работать для произвольных rows, а не искать имя ошибки из фикстуры.

Базовый уровень — окно, точные ID и разделение matches/context; затем добавьте лимит.
Для быстрых: отрицательный тест на похожий ID, неполный источник или конфликт идентификаторов.
При затруднении попросите подсказку у ведущего.

## 11–15: проверки функции

```bash
python workshop/exercises/trace_to_logs/run.py check
python workshop/exercises/trace_to_logs/run.py trace_to_logs --case missing-logs
python workshop/exercises/trace_to_logs/run.py trace_to_logs --case no-ids
```

TODO должен дать FAIL; ваша реализация — `passed=true`, exit 0. Проверяются чужой ERROR,
похожий ID, время, отсутствие ID, недоступный источник, неполный/пустой trace и лимиты.
`ok` означает чтение доступных файлов, а не подтверждение причины или полноты.
Смотрите coverage, limitations и skipped_invalid_timestamps.

## 15–20: расследование выбранным агентом

### Codex / Claude Code / Cursor: нативный MCP

После изменения функции **перезапустите qai_application**, чтобы сервер загрузил новый код.
Аргументы: `--mode replay --case complete`. Подтвердите вызовы сервера.
Для Codex используйте обычную авторизацию по подписке; API-ключ серверу не нужен.

Передайте в новом диалоге:

```text
Расследуй BUG-LAB-01 по общим правилам QAI из workshop/prompts.
Все первичные данные получай только через MCP qai_application в режиме synthetic file replay.
Начни с qai_begin, схемы бери из qai_catalog, инструменты вызывай через qai_observe.
Сам выбирай роли и досбор. Если роли не разделяют один MCP-процесс, выполни их в основной
сессии; не утверждай, что запускал субагентов. Используй мою реализацию trace_to_logs.
Проверь корреляцию, прочитай исходные логи для проверки чужих записей и код для проверки
механизма. Сохрани неизвестное влияние пропусков. При needs_evidence не подтверждай RCA.
Не читай solutions, INSTRUCTOR, тестовые эталоны и готовые отчёты. Ничего не меняй.
Отправь application draft через qai_validate того же сервера и покажи фактический результат.
```

Улики — `evidence[{claim, kind, evidence_ref}]`; kind: **ФАКТ / ВЫВОД / ГИПОТЕЗА**.
`culprit_files` — наблюдаемые file:line. Каталог и tool_observations заполняет сервер.
Нужен фактический `qai_validate.valid=true`, а не обещание модели проверить ответ.
Сохраните транскрипт и ответ валидатора в `workshop/.local/`. При отказе прочитайте errors;
не исправляйте сохранённый ответ вручную и не меняйте валидатор.

### Python: модельный оркестратор

С заранее настроенным API:

```bash
python workshop/exercises/trace_to_logs/orchestrator_replay.py --case complete --output workshop/.local/exercise-04-complete
```

Для этого replay доступен также транспорт Codex по подписке, без API-ключа:

```bash
codex login status
python workshop/exercises/trace_to_logs/orchestrator_replay.py --provider codex --case complete --output workshop/.local/exercise-04-codex
```

Нужен `Logged in using ChatGPT`. Это **Python-оркестратор с Codex как модельным транспортом**;
он отличается от нативной сессии редактора выше. Этот флаг не следует переносить в другие CLI.
Без `--provider codex` runner использует API; не запускайте такой вариант, если API не выбран.
Для повторения укажите новый output.

Модель выбирает роли и досбор; инструменты читают только файлы. Runtime раскрывает ссылки
в точные цитаты и проверяет обычный application-контракт. Сохраняются BUG-LAB-01.json,
trace, role-reports.json и validation.json. Exit 0 — контракт принят; exit 1 — отказ.
`behavioral_eval.status=not_run`: приватный ключ не входит в комплект. Смысл ответа проверьте сами.

### Общая приёмка

- Есть ваша функция и зелёный check.
- Агент фактически вызвал trace_to_logs с вашей реализацией.
- Контракт принят: Python runtime или MCP `valid=true`. Это не автоматическая проверка смысла.
- Причина объясняет симптом и подтверждена прочитанным кодом и связанными логами.
- Чужой ERROR исключён по наблюдаемым ID; здоровые pods не доказывают исправность приложения.
- Coverage и неизвестное влияние пропусков сохранены. Назван следующий шаг проверки.

High не обязателен: medium с объяснением ограничений допустим. Для недостаточных данных
допустим принятый low с пустой причиной и адресным запросом. Технический отказ валидатора
не равен принятому low. На 55-й минуте сохраняем результат, даже если этап не завершён.
Если модель идёт дольше оставшегося времени, используйте пару/резерв и отметьте непроверенное.

## Усложнения и резерв

После базовой приёмки выберите **один** вариант: missing-logs, incomplete-trace, no-ids или
invalid-trace. Это варианты данных одного бага, не новые дефекты. Python: новый `--case` и
output; редактор: измените case сервера, перезапустите и начните новое расследование.
При no-ids модель нового оркестратора работает, но runtime не разрешает checker читать код
и подтверждать RCA без корреляции. Проверяйте фактическое решение модели запросить данные.

На 11-й минуте ведущий может выдать **только correlate**. Отметьте помощь; всё равно выполните
check и аудит ответа. При недоступной модели check и файлы работают без неё. Сохранённый отчёт
ведущего пригоден для аудита, но не доказывает использование вашей функции моделью.
