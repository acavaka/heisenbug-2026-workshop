# 4. Помогите агенту найти логи нужного запроса

**20 минут.** Пользователь получил неправильную сумму заказа. В учебных файлах есть trace и логи нескольких сервисов, включая посторонние ошибки. Допишите функцию, которая выбирает записи нужного запроса. Затем попросите агента использовать её и объяснить ошибку суммы.

Вы научитесь добавлять агенту инструмент и проверять его применение. Регистрация инструмента и чтение файлов уже подготовлены: всю систему с нуля писать не нужно.

## Что меняем и что используем

Меняем только описание `description` и функцию `correlate` в [workshop/skills/trace_logs.py](../../skills/trace_logs.py). Данные, адаптеры, проверки и код checkout не меняем.

Это отдельный синтетический файловый кейс `BUG-LAB-01`. Живые Kubernetes, Tempo и API приложения здесь не вызываются. Для расследования в редакторе нужен заранее подключённый **qai_application**, режим `replay`, case `complete`, без `--solution`. [Настройка для ведущего](../../../docs/application-mcp.md).

Закончите задание 3. Откройте новый чат; сервер k8sgpt и старый investigation_id в этом задании не используются. Если работали через Python, откройте новый терминал без `QAI_MCP_CONFIG` и `REPORTS_DIR` предыдущего задания.

Все команды выполняйте из корня проекта — папки с `workshop/` и `fixtures/`.
Используйте подготовленное Python-окружение. В macOS/Linux:

```bash
source workshop/.venv/bin/activate
```

В Windows PowerShell:

```powershell
workshop/.venv/Scripts/Activate.ps1
```

## Шаг 1. Посмотрите, что произошло — 3 минуты

```bash
python workshop/exercises/trace_to_logs/run.py report
python workshop/exercises/trace_to_logs/run.py pods
```

Прочитайте обращение и снимок состояния. Откройте `workshop/skills/trace_logs.py`, найдите `correlate` и её описание: что функция получает на вход и что должна вернуть.

## Шаг 2. Допишите функцию — 8 минут

Нужно учитывать время, сравнивать ID целиком, отделять связанные строки (`matches`) от соседнего контекста (`context`), соблюдать лимит и сообщать об обрезанном результате (`truncated`). Адаптеры уже подготовили даты, ID и строки.

Можно писать самостоятельно или вставить в Codex, Claude Code или Cursor:

```text
Помоги дописать инструмент для учебного задания.
Прочитай workshop/exercises/trace_to_logs/README.md и workshop/skills/trace_logs.py.
Меняй только description и correlate в workshop/skills/trace_logs.py.
По существующему контракту реализуй отбор по окну времени, точным ID,
разделение matches/context, лимит и truncated. Алгоритм должен работать для произвольных rows.
В description объясни применение, поля результата и ограничения соседнего контекста.
Не зашивай имена ошибок, ID и диагноз. Не меняй адаптеры, данные, проверки и код checkout.
Не читай solutions, INSTRUCTOR, HINTS, тестовые эталоны и готовые отчёты.
Причину BUG-LAB-01 пока не расследуй. Покажи diff; проверки я запущу отдельно.
```

На 11-й минуте задания переходите к проверке. Если функция не готова, ведущий выдаст только `correlate`. Отметьте помощь и продолжайте: вам ещё нужно проверить инструмент и его использование агентом.

## Шаг 3. Проверьте функцию — 4 минуты

```bash
python workshop/exercises/trace_to_logs/run.py check
python workshop/exercises/trace_to_logs/run.py trace_to_logs --case missing-logs
python workshop/exercises/trace_to_logs/run.py trace_to_logs --case no-ids
```

Исходная TODO-заготовка должна давать FAIL. У готовой функции ожидаем `passed=true` и exit 0. Проверки включают чужую ошибку, похожий ID, время, неполные источники и лимиты.

В двух дополнительных выводах посмотрите `coverage` (какие данные получены), `limitations` (ограничения) и `skipped_invalid_timestamps` (строки с непригодным временем). `ok` означает успешное чтение доступных файлов, а не доказанную причину.

При FAIL вставьте в рабочий чат фактический вывод и запрос:

```text
Разбери этот вывод check и исправь только мою correlate в прежних границах.
Не меняй проверки и не читай эталонное решение.
Успех нужно подтвердить повторным check.
```

## Шаг 4. Дайте агенту использовать инструмент — 5 минут

Перезапустите подключённый **qai_application**, чтобы он загрузил изменённую функцию. Аргументы сервера: `--mode replay --case complete`, без `--solution`.

Откройте новый чат в Codex, Claude Code или Cursor и вставьте:

```text
Расследуй BUG-LAB-01 по общим правилам QAI из workshop/prompts.
Все первичные данные получай только через MCP qai_application в режиме synthetic file replay.
Начни с qai_begin, схемы бери из qai_catalog, инструменты вызывай через qai_observe.
Сам выбирай роли и досбор. Если роли не разделяют один MCP-процесс, выполни их в основной
сессии; не утверждай, что запускал субагентов. Используй мою реализацию trace_to_logs.
Проверь корреляцию, прочитай исходные логи для проверки чужих записей и код для проверки
механизма. Сохрани неизвестное влияние пропусков. При needs_evidence не подтверждай RCA.
Не читай solutions, INSTRUCTOR, тестовые эталоны и готовые отчёты. Ничего не меняй.
Отправь application draft через qai_validate того же сервера и покажи фактический результат.

```

Подтвердите разрешённые вызовы своего MCP. Агент должен начать новое расследование, получить данные через `qai_observe`, использовать `trace_to_logs` и показать фактический ответ `qai_validate`. Ссылка на улику относится только к этому расследованию. В формате ответа `kind` принимает ФАКТ / ВЫВОД / ГИПОТЕЗА; схемы агент получает от сервера.

Проверьте объяснение: какие логи относятся к запросу, какой код объясняет сумму, почему посторонняя ошибка исключена и что осталось неизвестным. Здоровые поды сами по себе не доказывают исправность расчёта.

## Если вы выбрали Python вместо редактора


С заранее настроенным API:

```bash
python workshop/exercises/trace_to_logs/orchestrator_replay.py --case complete --output workshop/.local/exercise-04-complete
```

Для этого replay доступен также транспорт Codex по подписке, без API-ключа:

```bash
codex login status
python workshop/exercises/trace_to_logs/orchestrator_replay.py --provider codex --case complete --output workshop/.local/exercise-04-codex
```

Нужен `Logged in using ChatGPT`. Это **Python-оркестратор с Codex как модельным транспортом**;
он отличается от нативной сессии редактора выше. Этот флаг не следует переносить в другие CLI.
Без `--provider codex` runner использует API; не запускайте такой вариант, если API не выбран.
Для повторения укажите новый output.

Модель выбирает роли и досбор; инструменты читают только файлы. Runtime раскрывает ссылки
в точные цитаты и проверяет обычный application-контракт. Сохраняются BUG-LAB-01.json,
trace, role-reports.json и validation.json. Exit 0 — контракт принят; exit 1 — отказ.
`behavioral_eval.status=not_run`: приватный ключ не входит в комплект. Смысл ответа проверьте сами.


## Что должно получиться

Сохраните в `workshop/.local/` свою правку, результат check, историю чата с расследованием и ответ валидатора. Отметьте, писали ли функцию сами или получили у ведущего.

Проверьте, что получилось:

1. Функция прошла check.
2. Агент действительно использовал её через trace_to_logs.
3. Проверка отчёта прошла: MCP вернул `valid=true` либо Python завершился без ошибки проверки.
4. Вы сверили объяснение с логами и кодом, исключили чужую ошибку по ID и сохранили ограничения.

Не нужно добиваться отметки high. Если данных мало, агент может оставить причину пустой, выбрать low и написать, что ещё нужно узнать. Такой ответ тоже должен пройти проверку. И наоборот: даже после успешного check прочитайте объяснение агента — проверка функции не проверяет смысл его ответа.

Если модель недоступна, выполните локальную проверку и разберите сохранённый отчёт ведущего. Отметьте: «Использование моей функции моделью не проверено». Через 20 минут сохраните то, что успели сделать.

В этом файловом примере модель может получать заранее заданное описание инструмента. Поэтому правку description посмотрите отдельно: по ответу модели нельзя уверенно судить, помогла ли именно она.

Если осталось время, попробуйте ещё один вариант данных — case — missing-logs, incomplete-trace, no-ids или invalid-trace. Это варианты данных того же бага. В редакторе меняйте case сервера, перезапускайте его и начинайте новое расследование. При отсутствии подтверждённой корреляции ожидается запрос данных, а не угаданный диагноз.
