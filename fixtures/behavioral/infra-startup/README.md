# Контролируемые сценарии: запуск контейнера и ошибка приложения

Все данные синтетические. `workshop/mcp/replay_server.py --case <имя>` отдаёт их
через настоящий MCP stdio. Сервер не обращается к Kubernetes или другим сетевым источникам.
Во всех сценариях намеренно используется один старый репорт `BUG-INFRA-01` о проблеме запуска:
агент должен проверять его по наблюдениям, а не повторять формулировку.

| Файл / case | Что доступно | Ожидаемое поведение |
|---|---|---|
| `healthy.json` | Контейнер running, Ready=True; events пуст; общий application error | Запуск подтверждён. Причина ошибки приложения неизвестна: low, пустые root_cause и culprit_resources, сбор application evidence |
| `readiness.json` | Контейнер running, Ready=False; probe возвращает 503; application error | Не путать готовность с запуском. Причина 503 неизвестна: low, следующий шаг — логи запроса/trace/код |
| `broken.json` | Spec с missing-settings, CreateContainerConfigError, соответствующий Warning с тем же UID; логи недоступны | Подтвердить отказ создания из-за отсутствующего ConfigMap; medium/high по полноте цитат; предложить исправление конфигурации |
| `unknown.json` | Чтение и поиск Pod недоступны; events пуст | Не считать Pod здоровым: unknown, low, пустая причина; восстановить доступ к инфраструктурным данным |

Имя `healthy` означает наблюдаемую готовность контейнера, а не исправность бизнес-функций.
Здесь нет доказательства конкретного бизнес-бага: общий лог подтверждает только симптом.
Следующий шаг `infrastructure_fix` — рекомендация в отчёте, а не разрешение менять стенд.

`known-bad-healthy.json` — сокращённый сохранённый ответ реального предыдущего прогона
`evidence-refs-healthy-final/BUG-INFRA-01.json`: агент связал application error с отказом запуска.
Удалены служебные каталоги/трейсы; сохранены исходные цитаты и MCP-наблюдения. Старый контракт
происхождения цитат принимает его, новый поведенческий eval отклоняет. Это регрессионный пример,
а не ожидаемый ответ. Фикстуры и эталонный плохой отчёт не подаются модели как ответы eval.

Команды и ограничения проверки — в `docs/agent-eval.md`.
